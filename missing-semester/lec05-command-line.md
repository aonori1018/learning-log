# Missing Semester 2020 第5回：コマンドライン環境 学習ノート

## 概要
- 範囲：本文（シグナル、ジョブ制御、tmux、エイリアス、ドットファイル、ssh、シェルのフレームワークとターミナルエミュレータ）＋演習
- 学べたこと：
  - Ctrl-C を押してからプロセスが止まるまでに、誰が何をしているか
  - bash の起動ファイルが読まれる順番
  - ssh の鍵認証とポートフォワーディング
- 環境：同じ PC に sshd と練習用ユーザーを作り、`ssh foobar@localhost` で練習した（終わったら片付けた）

## 学べたこと
1. Ctrl-C を押すとバイト3が届き、カーネルの端末の仕組み（`stty -a` の `intr = ^C`）が SIGINT に変えて、前面のプロセスに送る
2. シグナルを受け取った側の動きは「既定の動作／無視／自分の関数」の3通り。SIGKILL と SIGSTOP は捕まえられない。シグナルで終わると `$?` は 128＋番号
3. ジョブ制御：`fg`・`bg`、端末を閉じると SIGHUP、`nohup`（無視させる）と `disown`（ジョブ表から外す）
4. tmux はサーバーとクライアントに分かれている。端末を閉じてもサーバーには SIGHUP が届かないので、作業が残る
5. エイリアスは、bash が読む行の先頭の単語の置き換え
6. ログインシェルは `.bash_profile`・`.bash_login`・`.profile` のうち最初に見つかった1つだけを読む。Ubuntu では `.profile` が `.bashrc` を読む。対話かどうか（`$-` に `i` があるか）は、ログインかどうかとは別の軸
7. ドットファイルを `~/dotfiles` にまとめて、ホームにはシンボリックリンクを置く
8. ssh の鍵認証：秘密鍵は手元から出ない。パスフレーズはサーバーに送られない。秘密鍵が漏れたら、サーバーに登録した公開鍵を消す
9. `ssh -L 9999:localhost:8888` の `localhost` は、サーバー側の sshd が解釈する
10. `~/.ssh/config` を読むのは ssh 自身。最初に見つかった値が勝つ。Ubuntu の `sshd_config` は先頭の `Include` で `sshd_config.d/*.conf` を先に読むので、そちらが勝つ

## 手を動かしたこと
- シグナルを捕まえる Python スクリプトで、Ctrl-C と Ctrl-\ の違いを確かめた
- `~/dotfiles`（bashrc、bash_aliases、vimrc、tmux.conf、install.sh）を作り、シンボリックリンクで管理（第6回で GitHub に公開）
- `scp`・`rsync` でのコピー、`python3 -m http.server` ＋ `ssh -L` でトンネル
- `sshd_config.d/` に設定を書き、パスワードでのログインと root のログインを禁止して、`sshd -T` で確かめた

## つまずいたポイント
### 1. 条件を逆向きに使った
- 問題：`kill -0` でプロセスの存在を調べる問題で、外した
- 学び：`kill -0` は権限も確かめる。権限がなければ、プロセスがあっても失敗する
### 2. 推論を途中で止めた
- 問題：`.bash_login` を足したときの動きを、見つかったファイルの中身まで追わずに答えた
- 学び：「どのファイルが読まれるか」の次に「そのファイルが何を読むか」まで追う
### 3. プログラムとプロセスの区別
- 問題：「ssh はマシンに1つ」と考えた
- 学び：`ssh` は打つたびに別のプロセスになる。待ち受ける sshd と、接続する ssh は役割が違う
### 4. 長い手順を一度にやると止まる
- 1手順ずつ、コマンドの意味と予想される出力を確かめながら進めたら、最後までできた

## 気づき
- 「どのマシンの、誰が解釈するか」で考えると、`localhost` や `-L` が分かる
- 「最初に見つかったものが勝つ」は、PATH・起動ファイル・ssh の config・sshd_config に共通している

## 資料の注意（日本語訳）
- 「シェルがシグナルを送る」→ 送るのはカーネルの端末の仕組み
- `kill -t` → `kill -l`
- ssh のエイリアスの例は3か所誤り（閉じる `"` がない、`~/.id_ed25519` → `~/.ssh/id_ed25519`、`--port` → `-p`）
- Ubuntu で `.bash_profile` を作ると、`.profile`（→ `.bashrc`）が読まれなくなる
- ポートフォワーディングの図が2枚とも欠けている
