## 学べたこと
1. モードは5つ。ノーマルモードは左下に何も表示されない。ノーマルのカーソルは文字の上、挿入のカーソルは文字の間にある
2. キーはバイトで届く。Ctrl＋キーは下位5ビット（`& 0x1f`）、Esc は 27（＝Ctrl+[）、↑ は 27 91 65。`cat -v` で確かめた
   - Vim が「Esc」と「↑の始まり」を区別できるのは、バイトが届く間隔で判断しているから（`ttimeoutlen`）
3. バッファはファイルのメモリ上のコピー。`:w` で初めてディスクに書く。`:q` が守っているのはウィンドウではなくバッファの中身
4. スワップファイル（`.memo.txt.swp`）は一定間隔で書き出され、正常終了で消える。中の PID で二重編集を検出する
5. 文法は `[回数] 動詞 [回数] 名詞`。名詞が移動なら「カーソルから移動先まで」、テキストオブジェクト（`iw`、`i(`、`a{`）なら「カーソルを囲むもの全体」
6. `.` は直前の変更を繰り返す。マクロは、レジスタに入ったただのキーの並び（`:reg` で見える）
7. `:[範囲]s/パターン/置換/[フラグ]` は ed・sed と同じ形。`.*` はできるだけ長く一致する（最長一致）
8. Vim は起動時に、決まった順番で決まった場所のファイルを読む（`:scriptnames`）。`~/.vimrc` を置くと defaults.vim が読まれなくなる
9. `EDITOR` は export した環境変数として git などにコピーされ、git が vim を子プロセスとして起動し、終わったらファイルを読む

## つまずいたポイント
### 1. 名詞（移動）を「地点」と考えた
- 問題：`d$` を「行末の1文字を消す」と予想した
- 学び：移動の名詞は、カーソルから移動先までの「範囲」を表す
### 2. `dd` で消したものもコピーされる
- 問題：行の入れ替えで、`yy` してから `dd` していた
- 学び：`d` で消したものはレジスタに入るので、`ddp` で済む
### 3. 同じ変更を手で打ち直した
- 問題：`.` を知った直後でも手で打ち直し、`end=' '` と打ち間違えた。出力の `fizz buzz` を見て原因に気づいた
- 学び：繰り返しは `.` やマクロで機械にやらせる
### 4. 正規表現の最長一致
- 問題：1行にリンクが2つある行に置換をかけ、理想の結果を予想して外した
- 学び：`.*` はできるだけ長く取る。止めたいときは最短一致や `[^区切り]*` を使う（第4回で回収）
### 5. マクロが止まる理由
- 問題：`999@q` が止まる理由を「最後の行で `j` が無意味になるから」と答えた
- 学び：`j` は何もしないのではなく「エラー」になり、エラーでマクロ全体が止まる。もし何もしないだけなら、最後の行で動き続けて壊れる

## 気づき
- サーバーやコンテナには VS Code がなく vi がある。`git commit` や `crontab -e` でもエディタが開くので、最低限の Vim は必要
- 「もし〇〇だったらどうなるか」と考えると、性質の意味が分かる
- 普段は VS Code に Vim 拡張を入れて使い、ターミナルの小さな編集は Vim でやる
