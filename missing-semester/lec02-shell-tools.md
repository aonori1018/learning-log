# Missing Semester 2020 第2回：シェルツールとスクリプト 学習ノート

## 概要
- 範囲：本文（変数と文字列、関数と特殊な変数、終了ステータス、コマンド置換とプロセス置換、`[[ ]]`、globbing、shebang、`man`・`tldr`、`find`・`fd`・`locate`、`grep`・`rg`、シェル履歴、ディレクトリ移動）＋課題5問
- 学べたこと：
  - シェルが1行を処理する順番と、クォートがどの段階に効くか
  - 関数とスクリプトの違い（今のシェルか、子プロセスか）
  - 探す・まとめる道具（`find`・`grep`・`xargs`）の安全な使い方

## シェルが1行を処理する順番
① 単語に分ける（`|` `>` `<` `;` もここで見つける）→ `{}` を展開 → ② 代入かコマンド名か → ③ `$名前`・`$( )` を置き換える → ④ クォートの外で置き換えた部分を空白・タブ・改行で分け直す → `*` `?` を展開 → ⑤ クォートを外して argv を作り、起動する

| | クォートなし | `"…"` | `'…'` |
|---|---|---|---|
| `$` の置き換え（③） | する | する | しない |
| 空白・改行で分ける（④） | する | しない | しない |
| `*` `?` の展開 | する | しない | しない |
| `\|` `>` `;` などの記号 | 働く | ただの文字 | ただの文字 |

ルール：変数と `$( )` は必ず `"` で囲む。`*` は囲まない。

## 学べたこと
1. `foo = bar` が失敗するのは、②で `foo` がコマンド名になるから
2. `|` は①で決まるので、変数の中身がパイプや命令になることはない。文字列を①から読み直させる `sh -c`・`eval`・C の `system()` ではこの安全装置が外れる → OSコマンドインジェクション
3. `$0`・`$1`…・`$#`・`"$@"` は、C の `argv[0]`・`argv[1]`…・`argc - 1`・`argv[1]` 以降に対応する。`"$@"` は、`"` で囲んでも元の引数の区切りを保つ唯一の例外
4. 終了ステータスは、プロセスが終わるときにカーネルが預かり、親のシェルが `$?` に入れる。0が成功（C の真偽とは逆）。0〜255 の下位8ビットだけ
5. bash の `if` は、後ろのコマンドを実行して終了ステータスを見る（C のように式を見るのではない）。`[[ ]]` は比較の結果を 0/1 で返す。`[` は普通のコマンドなので④の影響を受ける
6. `$( )` は、コマンドの1番の出力（区切りの情報を持たない、ただの文字の並び）に置き換わる。`<( )` は `/dev/fd/63` のような「中身を読める場所の名前」に置き換わる
7. `*` `?` は今あるファイルと照らし合わせる（一致しなければそのまま残る）。`{}` はファイルを見ずに文字を作るだけ
8. 関数は今のシェルの中で、スクリプトは子プロセスで動く。だから `cd` や変数の変更は、関数なら残り、スクリプトなら親に残らない。`source` は、ファイルの中身を今のシェルで実行する
9. `man` は節で分かれている（1 コマンド、2 システムコール、3 C ライブラリ関数）。組み込みコマンドは `help`
10. `find` の `'*.py'` の `'` と `\;` の `\` は、シェルに先に解釈させず `find` に届けるため

## 課題で分かったこと
- 課題3（まれに失敗するスクリプトを、失敗するまで回す）
  - `>>file` と `2>&1` を別の行に書いてしまい、`file` が空だった。`wc -l file` で確かめて初めて気づいた
  - 条件と本体で `random.sh` を2回実行している欠陥には、自分で気づいた
  - 完成版では420回目で失敗し、`wc -l` が421行（成功419行＋失敗の2行）で、つじつまが合った
- 課題4（`find` と `xargs` で HTML を zip にまとめる）
  - `find | xargs zip` は空白入りのファイル名で壊れる（`xargs` が空白でも切るから）→ `xargs -d '\n'`
  - 改行を含む名前では `-d '\n'` も壊れる。ファイル名には NUL が入らない（カーネルに C の文字列として渡されるから）ので、`-print0 | xargs -0` が一番安全
- 課題5（一番新しく変更されたファイルを探す）：`find . -type f -printf '%T@ %p\n' | sort -n | tail -1`

## つまずいたポイント
### 1. `"$(ls)"` を「リスト」だと思った
- 問題：2つの引数になると答えた
- 学び：出力はただの文字の並び。改行を含む1つの文字列になる。区切りを保つのは `"$@"` だけ
### 2. `*` が何にも一致しないとき
- 問題：何も表示されないと答えた
- 学び：一致しなければ `*` はそのまま残る（変数が空になるのと混同していた）
### 3. 「開く」と「読む」の混同
- 問題：`echo < a.py` で中身が表示されると答えた
- 学び：シェルがファイルを開いて0番につないでも、`echo` は0番を一度も読まない。開くのと読むのは別の作業（`man 2 open` と `man 2 read`）
### 4. リダイレクトがかかる範囲
- 問題：別の行に書いた `>>file` が、以降の行に効くと考えた（課題3）
- 学び：リダイレクトは同じ行のコマンドにだけかかる
### 5. `source` の役割
- 問題：「スクリプトを関数にする」と説明した
- 学び：`source` はファイルの中身を今のシェルで実行するだけ。関数を定義しているのは中身の `marco () { … }`

## 気づき
- 権限のチェックは「開く」ときに行われる。開いた後で `chmod` しても、すでに開いているプロセスには効かない（`exec 3< a.py` で実験した）
- `chmod u-r a.py` のあと、`cat a.py`・`cat < a.py`・`sudo cat a.py`・`sudo cat < a.py` の4通りを自分で試し、エラーの先頭（`cat:` か `bash:` か）で、誰が開こうとして断られたかが分かった
- 道具の初期設定で見落とすことがある：`rg` は隠しファイルを探さないので、`.env` の秘密を探すには `rg -uu` が必要
- 危ないコマンドは、先に `echo rm foo*` で何が渡るか確かめる

## 資料の注意（日本語訳）
- `<( )` は「一時ファイル」ではなく、Linux の bash ではパイプ（`/dev/fd/…`）
- `rg -u` だけでは隠しファイルは探せない。公式の説明では `-uu` が必要
- 「コマンド代入」「プロセス代入」→ 一般的には「コマンド置換」「プロセス置換」
- `-mtime -1` は「一日前に変更された」ではなく、直近24時間以内
- fasd はリポジトリがアーカイブ（更新終了）。今なら zoxide
